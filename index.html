Operating procedure: working with Matthew

  1. 1

    Send the problem in writing

    Written context comes first. State the problem, the constraints and what has been tried.

  2. 2

    Define success and failure before building

    Scope the success metric. List the failure modes. Both are agreed before work starts.

  3. 3

    Ship the smallest live version

    Release behind evals. Expand only after the evals hold.

  4. 4

    Fail closed on safety-critical paths

    A safety-critical path that cannot decide stops, and pages a human.

  5. 5

    Hand off with documentation

    The system is documented so that it runs without him.
